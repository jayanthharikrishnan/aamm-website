# Activate the owner services

Render is connected and the existing service has been verified. It currently uses the free plan without a persistent disk. The owner ID and production origin are configured. The source is prepared for these services. Account approvals, secrets and durable hosting must be configured before they can operate. Enter secrets in Render's environment settings; do not send passwords, OTPs or API keys in chat or commit them to GitHub.

1. **Administrator access:** Your administrator ID is **9344898473**. In Render, set a unique `ADMIN_PASSWORD` of at least 12 characters. `ADMIN_ID` and `ADMIN_PHONE` can override the supplied owner account if needed. An ID alone never grants access. Administrator OTP is a separate, real Twilio verification to the configured owner phone; it becomes available only after step 2. Test successful sign-in, rejection of an incorrect password/code, and signout.
2. **OTP and optional SMS:** Set `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` and `TWILIO_VERIFY_SERVICE_SID` from your legitimate Twilio account. For order/billing SMS, also configure `TWILIO_MESSAGING_SERVICE_SID` or an approved `TWILIO_FROM_NUMBER`; Verify alone does not enable general messaging. Complete the provider's required account/KYC, Indian routing and any applicable DLT sender/template approvals. Confirm the requirements with the provider for your chosen Verify and transactional routes. Test an actual Indian number: receiving a genuine OTP, expiry/invalid codes and provider-confirmed delivery. Trial-account recipient restrictions may apply. A queued or sent message is not labelled delivered without provider confirmation.
3. **Payments and customer bills:** Add Razorpay **test** `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` and `RAZORPAY_WEBHOOK_SECRET`; configure the signed webhook at `https://aamm-6rvg.onrender.com/payments/webhook`. Review stock and final order amounts before confirmation. Test checkout, signature/capture verification, callback/webhook retries and refunds before switching merchant keys to live mode. Customer bills are order invoices/payment receipts, not subscriptions. They use actual order/payment records; no GST registration, tax invoice or fabricated business address is implied. Set `BILLING_BUSINESS_ADDRESS` only to your real verified business address.
4. **Persistent Render storage:** Attach a supported persistent disk, back up the current live database, restore that verified database to the disk once and set an absolute `DB_PATH` such as `/var/data/aamm/database.db`. Set `NODE_ENV=production` and the exact HTTPS `APP_ORIGIN`. Do not overwrite the database during each deployment. Verify record counts, a restart and an off-server backup. `/health` reports configuration/connectivity; it cannot prove the disk is durable. See [DEPLOYMENT.md](DEPLOYMENT.md) for the safe sequence.

The administration configuration screen reports missing settings without exposing their secret values. Real provider tests and Render storage verification remain required; code being present does not mean the services have been activated.
